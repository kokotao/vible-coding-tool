产品介绍 2025 年 5 月 阅读时长约 6 分钟

把 Codex 真正接进飞书和 QQ，
让 AI 编程进入日常协作流

灵犀桥连接 Codex / Claude 与飞书、QQ，让任务受理、执行、回告、确认形成真正闭环。

在很多团队里，AI 编程工具已经不再是"尝鲜"功能，而是实实在在进入了日常工作流。

问题是，工具很强，协作却常常断在最后一公里。

你可以在 Codex 里跑任务、写代码、修问题，但真正的沟通、确认、回报，依然散落在飞书群、QQ 机器人、终端窗口和网页后台之间。信息来回切换，不仅效率低，还容易丢上下文、漏状态、错确认。

灵犀桥，正是为了解决这个问题而生。

它是什么

灵犀桥是一个连接 Codex / Claude 与 飞书、QQ 的双向智能网关服务。

你可以把它理解成一座"桥"：

  • 一边连接 AI 编程工具，负责执行任务
  • 一边连接 IM 机器人，负责发起指令、接收结果、处理确认
  • 中间由网关统一完成路由、状态管理、风控和审计

它不是一个单纯的通知机器人，也不是一个只会转发消息的中转站。灵犀桥要做的是，让 AI 编程真正进入团队协作场景，形成"发起 — 执行 — 回传 — 确认"的闭环。

为什么需要它

现实里的 AI 编程协作，通常会遇到这几个痛点：

  1. 指令入口分散 — 有人习惯在群里说，有人习惯在网页点，有人习惯在终端里敲。消息来源多了，任务就容易散落。
  2. 任务状态不透明 — 任务到底有没有开始？现在卡在哪一步？最终结果回来了没有？这些问题只能靠"问人"来解决。
  3. 高风险操作缺少确认 — 删除、覆盖、重置、生产修改这类动作，如果没有二次确认，很容易出事故。
  4. 上下文容易断裂 — 谁发起的任务？对应的是哪个 session？结果该回给谁？信息一多就乱了。

灵犀桥做的事情很直接：把这些碎片重新拼成一条清晰、可追踪、可确认的链路。

它能做什么

1. 用飞书或 QQ 直接驱动 Codex

在群里或机器人对话里发出自然语言指令，灵犀桥会把消息送到对应的 Codex 会话中执行。比如： 

#session:demo 帮我修复登录接口 500 问题
#session:demo 补一组单测并告诉我结果
#session:demo 检查这个任务是否能直接发布

对使用者来说，不需要切换到另一个系统重新描述问题，原本的聊天场景就能直接变成工作入口。

2. 把执行状态再回推到 IM

灵犀桥不是只"发出去"。它还会把任务的关键状态回传回来，让你在飞书或 QQ 里就能看到：

  • 已受理
  • 执行中
  • 已完成
  • 失败
  • 需要确认

这意味着你不用一直盯着终端，也不用反复刷新网页后台。任务状态本身就会回到你最常用的沟通场景里。

3. 通过 session 显式路由，减少串任务

灵犀桥采用显式 #session:<id> 路由方式。它的好处很直接：

  • 同一个群里可以同时管理多个任务
  • 同一个 session 可以持续承接上下文
  • 不容易把别人的指令发错会话

对经常多人协作、多人同时发任务的团队来说，这一点尤其重要。

4. 对高风险动作做二次确认

灵犀桥内置风控策略，会对高风险操作进行确认拦截：

  • 不是所有自然语言指令都应该直接执行
  • 删除、重置、覆盖、批量修改这类动作，必须再确认一次
  • 确认通过后才真正执行

这让 AI 编程更适合进入真实团队环境，而不是停留在个人试验阶段。

5. 提供网页管理台做辅助观测

灵犀桥的主交互面仍然是飞书和 QQ，对话才是最自然的入口。

但它同时也提供网页管理台，用来查看会话状态、任务状态、风控记录和机器人接入情况。

IM 负责操作，网页负责观测，分工清晰，也更符合真实使用习惯。

适合谁

灵犀桥尤其适合下面这些场景：

  • 已经在用 Codex、Claude 或类似 Vibe Coding 工具的人
  • 团队主要在飞书或 QQ 里协作的人
  • 希望把 AI 编程接入现有消息流的人
  • 需要任务状态回传、审计和确认机制的人
  • 想把"能用"升级成"可落地、可协作、可追踪"的人
如果你不想把 AI 编程停留在一个独立工具里，而是希望它真正融入团队协作流程，灵犀桥会是一个很顺手的入口。

现在已经做到什么程度

灵犀桥目前已经不是一个概念稿，而是一个持续演进中的可用项目。

当前方向包括：

  • Node.js + TypeScript 的网关服务
  • SQLite 作为基础存储
  • 飞书接入与 QQ 接入
  • Codex 任务派发与事件回传
  • 任务、会话、风控、审计等状态管理
  • 网页管理台和基础运维能力

换句话说，它已经具备了"从消息到执行、从执行到回报"的完整闭环雏形。

上手并不复杂

对于本地试用，灵犀桥的体验尽量保持简单：

npm install
npm run dev

如果你要启用飞书或 QQ 的桥接能力，也可以继续按项目提供的命令启动对应长连接服务。项目本身也支持命令行短入口，安装后可以直接用 vct 启动。

结语

AI 编程工具的下一个阶段，不只是"更聪明"，而是"更好地融入工作流"。

灵犀桥正是在做这件事：把 Codex 这样的执行能力，接到飞书和 QQ 这样的协作入口上，让 AI 真正进入团队的日常沟通链路。

如果你也在寻找一个把 AI 编程落到实际协作场景里的方案，灵犀桥值得试试。
