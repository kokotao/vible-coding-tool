# 方案B后台鉴权与统一命令入站执行计划

## 目标

- 收敛后台管理接口的匿名访问面。
- 抽出公共命令入站服务，统一 Web / Feishu / QQ 的任务建档、风控与调度上下文。
- 为高风险确认恢复补齐任务调度上下文持久化。

## 本次落地

1. 新增统一后台鉴权模块 `src/modules/security/admin-auth.ts`
- 对高风险管理写接口统一校验 `x-viblect-admin-intent`
- 支持可选 `WEB_ADMIN_TOKEN`
- 无 token 时默认限制为本地回环访问

2. 新增公共命令入站服务 `src/modules/commands/command-intake-service.ts`
- 统一创建 `tool_sessions / tasks / messages`
- 统一风险判断与 `risk_confirmations`
- 统一持久化任务调度上下文

3. 新增任务调度上下文仓储
- `src/storage/repositories/task-dispatch-context-repository.ts`
- `task_dispatch_contexts` 表保存 `threadRef / projectPath / model / reasoning`

4. 接入现有入口
- `FeishuWebhookService`
- `QqWebhookService`
- `CodexWebChatService`
- `LightOpsService` 风险确认恢复时复用持久化上下文

5. 收紧后台配置接口
- `/api/connectors/:platform/config` 改为脱敏返回
- `appSecret` 改为“空值不覆盖旧值”
- 前端连接配置页不再回显明文 secret

6. 收紧本地会话发送
- 删除 Web send 的 `projectPath` API 透传
- 同 session 活跃任务时返回 `SESSION_BUSY`

## 验证

- `npm test`
- `npm run build`

## 后续建议

1. 若要进一步提升管理面安全性，可补完整登录态或一次性配对流程，而不只依赖本地 token/header。
2. 若要减少本地会话页首次接入成本，可补一个明显的 `adminToken` 设置入口，而不只依赖 URL query/localStorage。
