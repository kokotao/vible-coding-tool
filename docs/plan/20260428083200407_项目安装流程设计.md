# vible-coding-Tool 项目安装流程设计（V1）

## 1. 目标

设计一套“可快速上手 + 可逐级启用能力 + 可验收回滚”的安装流程，适用于：

- 本机开发联调（默认）
- 飞书长连接接入
- Codex 任务自动回推

## 2. 安装分层

采用分层安装，避免一次性配置过重：

1. L0 基础依赖层：Node 环境与仓库依赖
2. L1 网关运行层：服务启动、健康检查、SQLite 初始化
3. L2 飞书接入层：长连接桥接与事件回调验证
4. L3 Codex 回推层：任务状态自动回推飞书

建议执行策略：`L0 -> L1` 必做，`L2/L3` 按场景开启。

## 3. 标准安装流程

### 3.1 L0 基础依赖层（必做）

建议版本：

- Node.js：`20.x LTS`（推荐）
- npm：`>=10`

执行命令：

```bash
cd /Users/albertluo/workSpace/albertLuo/vible-coding-Tool
cp .env.example .env
npm install
```

跨平台一键命令（推荐）：

```bash
npm run install:check
```

Windows 命令（可选）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

```bat
scripts\install.cmd
```

校验命令：

```bash
node -v
npm -v
```

验收标准：

- `node_modules` 安装完成
- 仓库根目录存在 `.env`

### 3.2 L1 网关运行层（必做）

启动服务：

```bash
npm run dev
```

健康检查（新终端）：

```bash
curl -sS http://127.0.0.1:3000/health
```

验收标准：

- 返回 HTTP 200
- 首次启动自动创建 `./data/gateway.db`

### 3.3 L2 飞书接入层（按需）

前置：

- 飞书后台应用已启用“长连接接收事件”
- 已订阅 `im.message.receive_v1`

启动桥接器：

```bash
npm run feishu:ws
```

说明：

- 优先读取环境变量 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`
- 若未配置环境变量，会尝试从网关配置 `/api/connectors/feishu/config` 读取
- 若网关配置了 `FEISHU_VERIFY_TOKEN`，桥接器需使用相同值

验收标准：

- 飞书后台“重新验证”成功
- 飞书向机器人发消息后，网关可收到并处理事件

### 3.4 L3 Codex 回推层（按需）

方式 A：按任务包装执行（推荐）

```bash
npm run codex:run -- --session feishu-codex-demo --title "安装流程验收" -- npm run test
```

方式 B：全局 watcher（已默认由网关启动，可手动单独拉起）

```bash
npm run codex:watch -- --session feishu-codex-demo --recipientOpenId <open_id>
```

验收标准：

- 任务状态可见 `running -> succeeded/failed`
- 飞书收到对应任务状态回推消息

## 4. 配置建议（按环境）

### 4.1 本地开发环境

- `HOST=127.0.0.1`
- `PORT=3000`
- `CODEX_CLI_SKIP_GIT_REPO_CHECK=true`

### 4.2 演示/联调环境

- 增加 `CODEX_INGRESS_TOKEN`
- 增加 `CODEX_INGRESS_SIGNING_SECRET`
- 固定 `CODEX_WATCH_SESSION_ID`、`CODEX_WATCH_RECIPIENT_OPEN_ID`

### 4.3 全局 CLI 安装（可选）

支持类似 `npm install -g` 的 CLI 体验，安装后直接执行短命令 `vct`：

```bash
npm install -g @tauchun/viblect
vct
```

本地未发布调试可用：

```bash
npm link
vct
```

## 5. 安装验收清单（Checklist）

- [ ] 已复制 `.env.example` 为 `.env`
- [ ] `npm install` 成功
- [ ] `npm run dev` 启动成功
- [ ] `GET /health` 返回 200
- [ ] 生成 `data/gateway.db`
- [ ] （可选）飞书长连接验证通过
- [ ] （可选）Codex 回推链路验证通过

## 6. 常见失败点与处理

1. 端口占用（3000）

- 现象：`npm run dev` 启动失败
- 处理：修改 `.env` 的 `PORT`，并同步更新 `GATEWAY_URL`

2. 飞书桥接器无法认证

- 现象：飞书后台验证失败
- 处理：核对 `FEISHU_APP_ID/FEISHU_APP_SECRET`，并确认 `FEISHU_VERIFY_TOKEN` 与网关一致

3. 未收到 Codex 回推

- 现象：任务完成但飞书无通知
- 处理：检查 `GET /api/debug/watcher`，确认 `running=true` 与最近推送时间

## 7. 回滚与恢复

最小回滚策略：

1. 停掉 `dev` 与 `feishu:ws` 进程
2. 恢复 `.env` 到已验证版本
3. 备份后删除 `data/gateway.db`（仅在允许丢弃本地测试数据时）
4. 按 `L1` 重新启动并做健康检查
