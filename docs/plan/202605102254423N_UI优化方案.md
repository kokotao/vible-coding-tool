# UI 优化方案（可落地）

## 1. 目标
- 统一项目的视觉语言，让管理台、宣传页、README 面板看起来像同一产品。
- 提升首页的信息层级，让用户 3 秒内知道“当前状态、下一步动作、核心入口”。
- 优化关键交互反馈，让任务、会话、连接状态更容易理解和操作。

## 2. 现状判断
- 管理台页面偏暖色玻璃风，信息密度较高，但入口层级还可以更清楚。
- 宣传页偏深色科技风，表现力强，但与管理台品牌语气不完全一致。
- README 面板是单独的浅色浮层风格，和主站存在明显视觉断层。

## 3. 设计原则
- 先统一，再美化。
- 先任务导向，再装饰。
- 先关键路径，再边缘页面。
- 尽量复用现有结构和组件，不做大重构。

## 4. 推荐方案
### 方案 A：轻量统一 + 局部增强
适合当前阶段，改动小、收益快。
- 保留现有首页布局。
- 统一颜色、阴影、圆角、按钮、状态标签。
- 首屏强化“系统状态 + 系统配置 + 主入口”。
- README 面板做成和主站一致的卡片语言。

优点：快、风险低、容易验证。
缺点：结构变化有限，整体升级感中等。

### 方案 B：首页驾驶舱重排
在 A 的基础上重排首页结构。
- 首屏改成“总览区 + 操作区 + 状态区”。
- 左侧展示任务和会话，右侧固定连接中心与系统配置。
- 增加空状态、加载态、错误态的统一样式。

优点：更像产品控制台，信息更清晰。
缺点：需要改较多首页布局。

### 方案 C：全站品牌统一升级
同时统一首页、宣传页、README 面板、按钮和动效。
- 建立完整 design tokens。
- 统一字体、色板、卡片层级、动效和插图风格。
- 形成一套完整品牌体验。

优点：最好看、最完整。
缺点：成本最高，不适合作为第一步。

## 5. 推荐路径
先做方案 A，再推进方案 B。
原因：
- 先把品牌和视觉语言统一，立刻能见效。
- 再重排首页信息结构，收益会更明显。
- 最后再考虑宣传页和全站统一，不会一次改太大。

## 6. 可落地改造清单
### 6.1 视觉统一
- 统一主色、强调色、状态色。
- 统一卡片圆角、边框透明度、阴影强度。
- 统一按钮高度、字体粗细、hover 反馈。
- 统一标题层级和正文行高。

### 6.2 首页优化
- 首屏增加“系统运行状态”与“下一步操作”区块。
- 把最常用入口前置：健康检查、系统配置、任务总览、会话入口。
- 让状态标签更直观：运行中、待确认、失败、已完成。
- 增加空状态提示，避免没数据时页面显空。

### 6.3 交互优化
- 关键按钮增加明确反馈与禁用态。
- 风险动作增加确认层。
- 加载中显示骨架或占位状态。
- 错误态给出下一步建议，而不是只报错。

### 6.4 宣传页优化
- 保留强视觉，但和管理台共用 logo、色板、按钮样式。
- 文案从“宣传语”改成“价值 + 场景 + 行动”。
- 让 CTA 更集中，减少次要链接干扰。

## 7. 分阶段落地
### Phase 1：基础统一
- 统一 token。
- 统一按钮、卡片、状态标签。
- 统一 README 面板视觉。

### Phase 2：首页重排
- 调整首页首屏结构。
- 强化任务导向信息层级。
- 优化空状态与状态反馈。

### Phase 3：品牌升级
- 统一宣传页和管理台视觉语言。
- 补少量动效和细节装饰。
- 做最终视觉验收。

## 8. 验收标准
- 首页用户能在 3 秒内找到主要入口。
- 页面视觉风格统一，不再像多个项目拼接。
- 关键状态和操作能被快速识别。
- 移动端和窄屏下仍保持可读、可点。

## 9. 风险
- 一次改太多容易打散现有稳定布局。
- 如果 token 不先统一，后续页面会继续分裂。
- 宣传页和管理台的视觉方向要保留差异，但不能冲突。

## 10. 建议的下一步
- 如果你想快一点：先做 Phase 1。
- 如果你想直接提升产品感：Phase 1 + Phase 2 一起做。
- 如果你要，我下一步可以直接按这个方案开始改首页和样式。
