# @tauchun/viblect npm 发布 SOP

> 适用对象：本仓库维护者。目标是把 `vible-coding-Tool` 作为 npm CLI 包发布到官方 npm registry，并保证 README 图片、CLI 命令、发布清单和线上版本可核验。

**目标：**稳定发布 `@tauchun/viblect`，并让用户可通过 `npm i -g @tauchun/viblect@latest && vct` 安装使用。

**范围：**
- 官方 npm 发布
- README 图片一起发布
- CLI 命令入口 `vct`
- 发布前安全检查
- 发布后版本核验

---

## 1. 包约定

- npm 包名：`@tauchun/viblect`
- 全局命令：`vct`
- 兼容命令：`viblect`、`vible-gateway`
- 发布 registry：`https://registry.npmjs.org`

## 2. 发布前置条件

### 2.1 账号与权限

- 已登录 npm 官方源
- 账号可见：`npm whoami --registry=https://registry.npmjs.org`
- 账号策略：
  - `auth-and-writes`：发布需要 6 位 OTP
  - `granular token + bypass 2FA`：可免 OTP 发布

### 2.2 本地环境

- Node.js 可用
- npm 可用
- 仓库根目录存在完整构建所需文件
- README 图片文件存在于仓库根目录：
  - `image.png`
  - `image-1.png`

### 2.3 registry 约束

- 发布命令必须显式指向官方源：
  - `--registry=https://registry.npmjs.org`
- 如果本机 `~/.npmrc` 默认指向镜像源，发布时必须覆盖

## 3. 发布清单

发布前必须确认以下内容：

- `package.json` 的 `name/version/bin/files/publishConfig` 正确
- `files` 白名单包含：
  - `dist/src`
  - `public`
  - `bin`
  - `README.md`
  - `image.png`
  - `image-1.png`
- `prepack` 会执行构建
- `prepublishOnly` 会执行 `publish:check`
- `publish:check` 不允许这些路径进入包：
  - `.env*`
  - `data/`
  - `docs/`
  - `tests/`
  - `src/`
  - `scripts/`
  - `.playwright-mcp/`
  - `.superpowers/`

## 4. 发布步骤

### 4.1 检查当前版本

```bash
cat package.json | rg -n '"version"'
npm view @tauchun/viblect version --registry=https://registry.npmjs.org
```

如果 npm 上已有相同版本，先升补丁号：

```bash
npm version patch --no-git-tag-version
```

### 4.2 预检

```bash
npm run publish:check
npm run build
```

### 4.3 打包预览

```bash
npm pack --dry-run --json
```

预期结果：

- `README.md` 在包内
- `image.png` 和 `image-1.png` 在包内
- `dist/src` 在包内
- 不出现 `.env`、`data/`、`docs/`、`tests/`、`scripts/`

### 4.4 正式发布

#### 方案 A：账号需 OTP

```bash
npm publish --access public --registry=https://registry.npmjs.org --otp=<6位验证码>
```

#### 方案 B：granular token + bypass 2FA

建议把 token 放进临时 `userconfig` 文件，避免污染本机默认 `.npmrc`：

```bash
cat > /tmp/npmrc-publish-viblect <<'EOF'
registry=https://registry.npmjs.org/
//registry.npmjs.org/:_authToken=<YOUR_TOKEN>
EOF

npm publish --access public --registry=https://registry.npmjs.org --userconfig=/tmp/npmrc-publish-viblect
```

发布后删除临时文件：

```bash
rm -f /tmp/npmrc-publish-viblect
```

## 5. 发布后核验

### 5.1 版本核验

```bash
npm view @tauchun/viblect@latest version --registry=https://registry.npmjs.org
npm view @tauchun/viblect versions --json --registry=https://registry.npmjs.org
npm dist-tag ls @tauchun/viblect --registry=https://registry.npmjs.org
```

### 5.2 安装核验

```bash
npm i -g @tauchun/viblect@latest --registry=https://registry.npmjs.org
vct
```

### 5.3 包内容核验

确认以下内容存在于线上包：

- `bin/vible-gateway.js`
- `README.md`
- `image.png`
- `image-1.png`
- `dist/src/...`

## 6. 常见失败与处理

### 6.1 `E404` 版本不存在

原因：

- 版本尚未发布
- 或查询用了错误 registry / 缓存源

处理：

- 加上 `--registry=https://registry.npmjs.org`
- 再查一次 `npm dist-tag ls`

### 6.2 `EOTP`

原因：

- 账号策略要求 2FA OTP
- 或 OTP 过期

处理：

- 使用认证器 App 里当前最新 6 位码
- 重新执行 `npm publish --otp=<code>`

### 6.3 `E403 Two-factor authentication or granular access token...`

原因：

- 传入的 token 没有 publish 权限
- 或账号要求 2FA 发布，而 token 没有 bypass 权限

处理：

- 使用正确的 granular token
- 或改走 OTP 发布

### 6.4 镜像源干扰

现象：

- `npm login` 打开了 `npmmirror/cnpm` 页面
- `npm view`/`npm publish` 行为不稳定

处理：

```bash
npm config set registry https://registry.npmjs.org
```

发布时仍建议显式带 `--registry=https://registry.npmjs.org`

## 7. 回滚策略

npm 已发布版本不建议依赖“删包”处理，优先使用以下方式：

1. 立即发布修复版，例如 `0.1.4`
2. 对错误版本做 deprecate：

```bash
npm deprecate @tauchun/viblect@0.1.3 "broken release, use 0.1.4"
```

3. README 和发布说明补充修复版本号

## 8. 安全要求

- 不要把 npm token 提交到仓库
- 不要把 token 写入长期 `.npmrc`，除非明确需要
- 发布完成后撤销不再使用的 token
- `publish:check` 必须一直保留
- `files` 白名单要明确，避免把 `.env`、`docs`、`tests` 一起发出去

## 9. 本次发布经验

- 使用 `--userconfig` 可以绕开本机默认 `.npmrc` 的镜像源和旧 token 干扰
- `npm view version` 有时会受同步影响，`npm dist-tag ls` 和 registry 原始 JSON 更可靠
- README 图片必须显式加入 `files` 白名单，否则不会进入 npm 包
- `auth-and-writes` 账号即使是新包也需要 OTP
